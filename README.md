# AI 求职助手 · BOSS 直聘版

在自己的浏览器里运行 AI 求职工作流：采集 BOSS 直聘岗位，评估匹配度，按岗位定制简历 PDF 和招呼语，追踪投递，并在 HR 发来新消息时生成可直接发送的回复草稿。

**默认是半自动模式**：AI 负责分析和草稿，所有消息仍然由你点确认后发送。项目还提供一个**默认关闭**的「单职位页自动打招呼」开关：开启后，仅对匹配分达标且未投递的岗位，在倒计时结束后自动发送招呼语；不会批量遍历搜索结果，也不会自动发送简历附件。项目不包含验证码绕过、指纹伪装或批量轰炸逻辑。

> 设计思路参考了 [ai-job-search-dev/ai-job-search](https://github.com/ai-job-search-dev/ai-job-search) 的「岗位评估 + 定制简历」流程，本仓库是面向 BOSS 直聘的独立实现。

---

## 功能

- **岗位采集**：在 BOSS 职位详情页通过扩展读取岗位名称、公司、薪资、地点、JD、HR 信息和标签；也支持搜索结果页（左侧列表 + 右侧详情），识别当前选中的职位卡片；读取失败时可以手动粘贴 JD。
- **匹配分析**：从技能、经验、行业、硬性条件和成长潜力五个维度评分，输出匹配点、缺口、风险、建议追问和投递切入角度。
- **定制简历**：基于你维护的结构化档案，挑选最相关的经历和项目，按 JD 改写措辞，生成中文 A4 PDF；自动检查页数并缩放字号。
- **反编造约束**：提示词 + 服务端事实校验双重约束。公司、职位、时间、学校、项目必须能在档案中找到；简历中的数字必须能在档案中找到，否则会被移除。
- **招呼语**：生成 80-140 字的 BOSS 风格首条消息，可在面板中编辑，支持一键填入或确认发送。
- **单职位页自动打招呼**：默认关闭。开启后，打开职位详情会自动分析，匹配分达标且未投递时生成招呼语，倒计时结束自动发送；倒计时期间可取消。
- **投递追踪**：记录打招呼消息、关联简历、投递时间、状态和时间线；服务端强制执行每日上限和最小投递间隔。
- **HR 回复草稿**：聊天页监听新消息，自动生成回复草稿；发送前由你确认。薪资、面试时间、联系方式等敏感信息有额外约束。
- **定制简历附件**：生成 PDF 后可下载、预览；在聊天页会尝试自动选择 PDF 文件。不同版本的 BOSS 页面可能限制脚本设置附件，失败时会提示手动发送。
- **本地优先**：资料、聊天和简历只存在本机 `.data/`；只有调用模型时才会把必要内容发送给你配置的模型服务商。

## 架构

```
┌──────────────────────────────┐
│ Chrome 扩展（MV3）            │
│ 页面面板 / 采集 / 聊天监听    │
│ 发送招呼语 / 选择 PDF 附件    │
└──────────────┬───────────────┘
               │ chrome.runtime 消息
┌──────────────▼───────────────┐
│ 本地 Fastify 服务 127.0.0.1  │
│ 配对鉴权 / 数据 / 提示词      │
│ 事实校验 / 投递风控           │
└───────┬──────────────┬───────┘
        │              │
┌───────▼──────┐ ┌─────▼──────────────┐
│ JSON 数据存储 │ │ OpenAI 兼容模型 API │
│ .data/        │ └────────────────────┘
│ 简历 HTML/PDF │ ┌────────────────────┐
└──────────────┘ │ 本机 Chrome/Edge   │
                 │ HTML -> PDF        │
                 └────────────────────┘
```

管理后台由本地服务托管，扩展通过后台服务 worker 调用本地 API。API Key 只保存在本地服务，扩展和浏览器前端不会拿到明文 Key。

## 环境要求

- Node.js 20+
- Google Chrome 或 Microsoft Edge（用于把简历 HTML 渲染成 PDF）
- 一个 OpenAI 兼容模型接口，例如 DeepSeek、通义千问、Kimi、OpenAI，或自建兼容服务
- 你自己的 BOSS 直聘账号

## 快速开始

### 1. 安装依赖并构建

```bash
npm install
npm run build
npm start
```

启动后打开：

- 管理后台：`http://127.0.0.1:8787`
- 健康检查：`http://127.0.0.1:8787/api/health`

控制台会打印数据目录、Chrome 检测结果和访问令牌位置。令牌用于扩展与管理后台配对，通常不需要手动填写。

### 2. 配置模型

进入「设置 → 大模型」，选择预设或填写任意 OpenAI 兼容接口：

| 服务 | API 地址 | 模型示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `kimi-latest` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |

点击「保存并测试」验证连通性。也可以使用环境变量初始化（首次启动时生效）：

```bash
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-...
LLM_MODEL=deepseek-chat
```

### 3. 建立资料档案

进入「我的资料」：

1. 上传 PDF / DOCX / TXT 简历，或直接粘贴简历文本；
2. 点击「AI 解析成结构化资料」；
3. **逐项核对**公司、职位、时间、学历、业绩数字；
4. 保存。

这份档案是所有分析和简历定制的唯一事实来源。AI 可以改写措辞、调整顺序、删减无关内容，但不应该新增档案中不存在的事实。

### 4. 安装扩展

1. 确认已经执行 `npm run build`（或单独执行 `npm run build:extension`）；
2. 打开 Chrome 的 `chrome://extensions`；
3. 打开右上角「开发者模式」；
4. 点击「加载已解压的扩展程序」，选择本项目的 `apps/extension/dist` 目录；
5. 建议把扩展固定到工具栏。

扩展只在 `zhipin.com` 页面注入，并且只连接本机地址的本地服务。

### 5. 开始投递

1. 在 BOSS 直聘打开职位详情页；也可以停在搜索结果页，先点击左侧目标职位卡片，让右侧显示详情；
2. 点击页面右下角的 **AI** 悬浮按钮；
3. 在面板中点击「AI 分析岗位」；
4. 生成招呼语和定制简历，检查内容；
5. 点击「确认发送招呼语」：
   - 如果当前页面已经有聊天窗口，会直接填入并发送；
   - 如果点击「立即沟通」后页面跳转，面板会保存一条待发送招呼语，在新页面的面板中再次确认发送；
6. 如需要，点击「发送简历」尝试发送定制 PDF。如果 BOSS 页面限制了脚本附件，使用「下载」后手动在聊天窗口选择文件；
7. 回到管理后台「岗位与投递」查看记录、状态和时间线。

### 6. 处理 HR 回复

- 扩展在聊天页每 4.5 秒检查一次当前对话（页面不可见时暂停）。
- HR 发来新消息且「自动生成 HR 回复草稿」开启时，会在后台生成回复草稿，面板的「对话」标签会出现未读数量。
- 打开面板检查 HR 和岗位上下文，编辑草稿，点击「发送回复」。
- 关闭自动发送回复后，按钮只会把草稿填入聊天框，你需要回到 BOSS 手动点击发送。

### 7. 可选：单职位页自动打招呼

在「设置 → 自动打招呼」开启后：

1. 打开 BOSS 职位详情页（URL 需要包含 `job_detail`）；
2. 扩展自动打开面板并分析岗位；
3. 如果岗位已投递过，直接跳过；
4. 如果匹配分低于阈值（默认 80），只展示分析结果，不发送；
5. 达标后生成招呼语，进入倒计时（默认 5 秒）；
6. 倒计时期间可以在面板点击「取消」；
7. 倒计时结束自动发送招呼语并记录投递；不会自动发送简历 PDF。

如果点击「立即沟通」后页面跳转到聊天页，只有在新页面的聊天对象与目标岗位一致时才会继续自动发送；否则会转成待发送卡片，让你手动确认。

自动模式默认关闭。开启前请确认阈值和每日上限，并注意它会在没有第二次确认的情况下发送消息。如果 BOSS 页面已经打开，开启设置后刷新页面或切回该标签页，让扩展重新读取设置。

## 关键设计

### 简历事实校验

模型输出简历后，服务端还会做一次确定性校验：

- 工作经历的公司、职位、起止时间以档案为准，档案中不存在的经历直接移除；
- 项目名称必须能在档案中找到；
- 教育背景始终使用档案中的真实学校、专业、学历和时间；
- 简历 bullet 和个人简介中出现的数字必须能在档案原文中找到，否则移除该表述；
- 被移除的内容会写入「本次调整」，方便你检查。

这不能替代人工审阅，但可以拦住大部分“模型编造业绩数字”的问题。

### 投递风控

服务端在记录投递前强制检查：

- 每日上限（默认 20）；
- 两次投递之间的最小间隔（默认 30 秒）；
- 同一岗位不会重复记录；
- 扩展在发送前先调用预检查接口，避免消息已发出但记录被拒绝。

设置中的「每日上限」和「最小间隔」可以调整，但不建议把自动化频率调得过高。

### 页面适配

BOSS 页面结构会变化，扩展的 DOM 选择器集中在：

```
apps/extension/src/content/boss.ts
```

如果某次改版后无法读取岗位或聊天消息：

1. 优先使用面板中的「手动补全」和「手动填写岗位」；
2. 检查 `JOB_*`、`CHAT_*`、`MESSAGE_*` 选择器数组，并更新；
3. 执行 `npm run build:extension`，在 `chrome://extensions` 点击扩展的刷新按钮；
4. 重新打开 BOSS 页面。

## 已知限制

- **不会修改 BOSS 在线简历**。定制结果是 PDF 附件，在线简历由 BOSS 维护；HR 首先看到的通常仍是在线简历。PDF 需要你在聊天中发送。
- **自动附件是尽力而为**。页面结构、文件类型限制或风控弹窗都可能导致自动选择文件失败，此时会回退为下载后手动发送。
- **页面选择器可能失效**。BOSS 改版后岗位或聊天读取可能失败；此时使用手动填写/复制，或更新 `boss.ts` 中的选择器。搜索结果页的“当前选中职位”依赖卡片的选中状态、焦点或标题匹配，如果左侧列表改版，点击卡片后使用面板的「重新读取」或「复制页面诊断」。
- **不绕过平台风控**。遇到验证码、安全验证或异常提示时，工具会停止当前操作，不会尝试破解。
- **只支持 BOSS 直聘**。代码按“平台适配层 + 通用 AI 流程”组织，后续可以增加其他平台，但当前版本没有。
- **模型输出需要人工复核**。即使有事实校验，也请检查每条招呼语、简历和 HR 回复，避免错误信息发出。
- **聊天回复不做自动重试**。发送失败时不会自动重发，避免重复消息。
- **自动打招呼只处理单个职位页**。不会遍历搜索结果，也不支持后台队列；页面在后台标签或不可见时会停止自动发送。
- **自动模式不会自动发附件**。它只发送招呼语；定制简历仍需你在聊天窗口确认后发送。

## 风险与隐私

- BOSS 直聘的用户协议可能限制脚本化操作。高频、批量、无人值守投递可能导致账号被限制。本项目默认人工确认、每日限额、发送间隔，并明确不包含验证码绕过。可选的自动打招呼模式默认关闭，启用后会直接发送招呼语，请自行评估账号风险。
- 请只投递你确实愿意考虑的岗位，不要把 HR 当作压力测试对象。
- 分析时会把你的档案和岗位描述发送给配置的模型服务商；生成回复时会把最近对话发送给模型服务商。请确认服务商的数据政策。
- API Key 以明文保存在本机 `.data/db.json`。如果电脑多人共用，请限制文件权限或在用完后删除密钥。
- 简历 PDF 下载链接通过本地令牌鉴权，令牌可能出现在浏览器历史中；服务只监听 `127.0.0.1`，不要将端口暴露到公网。

## 常见问题

**扩展显示“本地服务未连接”**

确认项目根目录已运行 `npm start`，端口是 8787，并且面板中的服务地址是 `http://127.0.0.1:8787`。修改端口后需要同步扩展设置。

**PDF 没有生成**

服务端会自动检测 Chrome/Edge。如果安装在非标准路径，在管理后台设置中填写浏览器可执行文件的绝对路径。PDF 生成失败时仍会保留 HTML 版本。

**模型返回 401 / 404**

检查 API Key、模型名和 Base URL。大多数 OpenAI 兼容接口需要以 `/v1` 结尾；程序会自动补 `/chat/completions`。

**点击 AI 分析没反应**

先看面板里的错误提示。常见原因是资料未完善（姓名 + 至少一段经历）或模型未配置。扩展的错误会以红色 toast 显示。

**为什么没有自动发送简历附件**

不同 BOSS 版本的聊天文件入口不同，浏览器也限制脚本直接操作本地文件。扩展会尝试点击上传入口并设置 PDF 文件；失败时请下载后用聊天窗口的「+」手动发送。

**能不能全自动无人值守投递**

不建议，也没有默认提供。当前设计是“AI 草稿 + 人工确认”，另有一个可选的单职位页自动打招呼开关，受匹配分、已投递过滤、倒计时、每日上限和发送间隔约束。它不会批量遍历搜索结果。全自动批量投递既有平台规则风险，也会降低沟通质量。

**自动打招呼没有触发**

确认设置已开启、资料和模型已完成、当前 URL 包含 `job_detail`、页面在前台，并且该岗位未投递、匹配分达到阈值。开启设置后刷新 BOSS 页面或切回标签页，让扩展重新读取配置。每个职位在同一个标签页内只会自动尝试一次；取消或失败后可以用面板手动操作。
